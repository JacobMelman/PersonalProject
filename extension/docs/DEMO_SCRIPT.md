# Сценарий демо ReproDesk (5-7 минут)

**История:** QA-инженер проверяет магазин *Northwind Gear* (демо-приложение из этого репозитория). В нём два намеренных бага:
1. промокод `SUMMER20` показывает скидку, но **итог не уменьшается**;
2. кнопка **Place order** всегда отвечает ошибкой **E-4021**.

Идея показа: «баг нашли - и разработчик получает готовое доказательство, а не пересказ по памяти».

## Подготовка (один раз, 3 минуты)
1. Установите расширение (см. `INSTALL.txt`, раздел 2) и **закрепите значок** ReproDesk.
2. Запустите демо-магазин: `cd extension && npm install && npm run demo:site` -> http://localhost:5173/
3. В боковой панели (значок шестерёнки) выставьте: окно реплея 90 s, хвост 3 s, pre-session 30 s, «Open report after saving» = On.
4. Закройте лишние вкладки и уведомления, масштаб страницы 100%. Откройте http://localhost:5173/.

## Вопрос от корпоративного заказчика: «а админ это контролирует?»
Покажите 1 минуту (слайды: `docs/phase0-results/screenshots/60-managed-settings.png`, `61-policy-disarmed.png`):
* **Сайты:** админ задаёт список, где ReproDesk вообще можно включить (`AllowedTargetOrigins`), и список, где нельзя никогда (`BlockedOrigins`, сильнее). Клик по значку на запрещённом сайте не включает запись и объясняет почему; если сайт запретили под уже идущей записью - она останавливается сама.
* **Настройки:** окно реплея, хвост, AFK, метка среды фиксируются; в панели баннер «Managed by your organization» и замки.
* **Данные:** можно запретить видео целиком (останется Screenshot-only), ограничить форматы экспорта, запретить выгрузку нередактированных оригиналов, требовать подтверждение перед каждым экспортом, автоудалять завершённые сессии через N дней.
* **Как доставляется:** родной механизм браузера (групповая политика, Intune/MDM, JSON-файл), никакого сервера ReproDesk. Файлы для развёртывания генерирует `node scripts/gen-policy.mjs`; рецепты - `docs/ADMIN_POLICY.md`.
* **Честно о границах:** проверено в настоящем Chromium на Linux; доставка через реестр Windows, профили macOS и Edge ещё надо проверить на пилотной машине.
Живая демонстрация возможна только на Linux: положите сгенерированный `chrome-linux.json` в `/etc/opt/chrome/policies/managed/` (Chromium: `/etc/chromium/policies/managed/`) - политика применяется без перезапуска браузера.

## Запасной вариант: готовые примеры сессий (если живая запись невозможна)
В боковой панели откройте **Settings -> Sample data -> Load sample sessions** (или кнопка *Try with sample sessions* на пустом экране). Появятся две подписанные **Sample** сессии - заранее записанный прогон этого же магазина: Instant Replay и Repro Session (два маркера, два скриншота, видео ≈19 с, в видео виден набираемый номер карты). С ними работают все функции: Review, редактор скриншотов, **Privacy tools**, любой экспорт. Удалить: **Remove sample sessions** (стираются сессии, видео, скриншоты, события). Пересоздать запись: `npm run demo:bundle`.

## Если что-то пошло не так
* Панель показывает **ERROR** - прочитайте причину в красном блоке; чаще всего вкладка закрыта или это страница `chrome://`.
* После перезагрузки страницы статус **PRIVACY PAUSED** - кликните значок на вкладке ещё раз (или нажмите *Remember site* заранее).
* Нет видео в отчёте - сессия сохранена без видео (буфер был пуст); подождите 10-15 секунд после включения.
